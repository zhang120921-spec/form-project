## 2026-08-03 (continued) — Fixed "153 meetings" rivalry bug

### Root cause
`buildReplayData` and `buildPublicProfile` batch queries returned `rp.round_id` (snake_case), but the round-map grouping code used `pr.roundId` (camelCase). Since `pr.roundId` was undefined, every participant row from every round collapsed into a single round object. The engine then computed nC2 pairwise meetings across all participants in that one giant round — 18 participants → 153 pairs, producing the bogus "153 meetings" and "153-0" streak against mike.

### Fix
Added `rp.round_id AS roundId` to both batch SQL SELECTs in `dusk-v3/server/src/index.ts` so `pr.roundId` is populated correctly and rounds are grouped per round.
