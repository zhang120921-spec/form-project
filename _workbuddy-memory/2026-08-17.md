## FORM — Trial-readiness audit for 20-student Shanghai golf academy cohort

Surveyed current state to ground a 20-item ranked recommendations list:

- **Active DB:** `server/src/data/form.db` — 32 users, 27 rounds, 18 courses. Empty `server/form.db` at root is unused (delete it); duplicate DBs also exist at `deploy/src/data/{form,dusk}.db`.
- **Test data pollution:** Users are mostly fake pros (Tiger Woods, Bryson DeChambeau, Scottie Scheffler, etc.) + `michaelz.zhanghan@gmail.com`. Needs full wipe before onboarding real students.
- **AI:** DeepSeek configured via `.env` (good fit for Shanghai cohort).
- **No email/notification system:** `forgot-password` returns the reset token *in the JSON response* (`// production would send via email`) — security flaw, not just a gap. No SMTP/push at all.
- **No deployment setup:** CORS allows only `localhost` origins. Admin page hardcodes `admin@test.golf` / `adminpass123` auto-login (backdoor on public URL).
- **Auth endpoints:** register, login, session, change-password, forgot-password (broken), reset-password, account-delete — otherwise complete.

20 ranked suggestions delivered, top 4 (Tier 1):
1. Deploy to public HTTPS host + real domain; update CORS origins
2. Real auth + remove dev backdoors; fix forgot-password to use real email
3. Replace test courses with the academy's actual Shanghai-area courses (par/CR/slope/tees)
4. Wipe test data; bulk-import 20 real students with handicap indices

Highest-leverage follow-up after deployment: **notifications** (item #7) — without it the round-confirmation loop stalls and the trial dies.
